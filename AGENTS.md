# Cavisi Project Instructions

These instructions apply to the entire `brand/` repository.

## Mandatory bootstrap

Before performing any Cavisi brand, content, copy, planning, review, or publishing task:

1. Read `CODEX.md`.
2. Treat `skills/cavisi-content-ops/SKILL.md` as the parent content skill and routing authority.
3. Load only the child skill and references selected by the routing table in `CODEX.md`.

Do not treat the packaged `copywriter-co-he-thong.skill` file as an active skill. Project-local active skills are the folders under `skills/`.

## Parent-child authority

- The parent skill owns source routing, brand invariants, evidence classification, content status, approval markers, and final validation.
- Child skills execute bounded specialist work from the parent's handoff contract.
- A child skill must not strengthen claims, invent evidence, change the target audience, change the primary promise, or mark content production-ready.
- When the user calls a child skill directly, still apply the mandatory brand and evidence rules from the parent skill and `CODEX.md`.

## Repository discipline

- Preserve approved terminology, paths, identifiers, dates, source IDs, and review markers.
- Use the smallest sufficient change and do not modify unrelated brand files.
- Do not invent product facts, research, testimonials, analytics, approvals, owners, budgets, offers, urgency, scarcity, or deadlines.
- Public-facing copy must use plain Vietnamese suitable for readers aged 30+ and include the canonical Cavisi footer unless the user explicitly requests an internal-only artifact.
- Run the relevant skill or content validation after structural changes when a validator is available.
